# Pressure Station — 압력 주유 프로토타입

첨부한 기획 양식을 기반으로 만든 **단일 씬 Unity 프로토타입 v0.2.6 — 차량별 매출·연료 원가·주유 이익**입니다. 정상 주유는 손을 뗀 뒤 압력이 차량 저항 이하가 되면 판정하고, 허용 상한을 넘는 초과 주유는 압력과 관계없이 즉시 공급을 끊고 실패 처리합니다. 큰 실패 카드와 −80점, 목표 초과량, 최근·누적 감점으로 손실을 알립니다. 성공 시 짧은 반짝임과 떠오르는 점수, 원터치·퍼펙트 보너스를 표시합니다. 차량 3종, 잔여 연료·목표 계산, 동적 제한 시간, 소량 허용 오차와 기본 점수는 v0.2 설정을 유지하며 성공 보너스를 추가합니다. 매출·연료 원가·주유 이익 정산을 추가했습니다. 보유 현금·연료 재고·평판·신규 차량은 아직 추가하지 않았습니다. 엔진은 **Unity 6000.6.0f1**입니다. APK와 Windows 실행 파일은 다시 빌드하지 않았으며 `Builds/`의 기존 파일은 v0.1입니다.

## 실행

- Unity에서 `Assets/Scenes/GasStationPrototype.unity`를 열고 **Play**를 누르세요.
- 시작 화면에서 감압 속도를 고른 후 **영업 시작**을 누르세요.
- 하단 버튼을 **마우스 또는 터치로 길게 누르거나**, **스페이스 키**를 누르고 있으면 압력이 올라갑니다.
- 손을 떼면 압력이 내려가지만, 압력이 차량 저항보다 높은 동안에는 연료가 계속 들어갑니다.
- 목표보다 일찍 손을 떼고 최종량이 초록 구간에 들어오도록 맞추세요. 손을 뗀 상태에서 **압력이 차량 저항 이하가 되어 유량이 0이면 바로 판정**합니다. 부족하면 같은 고객에게 다시 눌러 이어갈 수 있으며, 남은 압력에서 다시 상승합니다.
- **허용 상한 초과 즉시 실패**: 버튼과 연료 공급을 즉시 끊고 그 순간의 주유량으로 −80점을 한 번만 적용합니다. 손을 뗀 뒤 잔류 주유로 상한을 넘는 경우에도 동일합니다. 큰 빨간 실패 안내를 1.2초 표시하고 0.5초 전환 후 다음 차량을 받습니다.
- 시간 초과는 버튼을 잠그고 자연 감압하며 유량이 멈추면 실패를 확정합니다. 감압 도중 과다 주유가 발생하면 즉시 초과 실패로 종료합니다.
- 영업 중 최근 감점·누적 감점을 계속 표시하고 결과 화면에도 누적 손실을 표시합니다. 현재 손실은 점수이며 아직 현금 시스템은 없습니다.
- **영업시간이 0이 되어도 현재 차량은 계속 주유할 수 있습니다.** 누르고 있던 입력을 유지하며, 부족하면 다시 눌러 이어갈 수 있습니다. 새 차량은 받지 않고 마지막 고객의 성공·실패 안내가 끝나면 영업 결과를 표시합니다. 차량 제한시간은 마감 후에도 계속 진행하며, 시간 초과·초과 주유의 실패 조건을 유지합니다.
- **Esc** 또는 우측 상단 `Ⅱ`: 일시정지 / 계속. 창 전환이나 앱 백그라운드 이동 시에도 입력을 해제하고 일시정지합니다.
- **F1** 또는 하단 `F1`: 테스트 패널. 게임은 멈추며 지금 놓았을 때의 예상 최종 주유량, 압력, 유량을 확인할 수 있습니다.

Windows 실행 파일을 생성한 경우 `Builds/Windows/PressureStation.exe`로 바로 실행할 수 있습니다. 실행 파일과 같은 폴더의 데이터 및 DLL 파일을 함께 보관하세요.

## Android 스마트폰 테스트

- Unity 메뉴 `Gas Station > Build Android APK`로 `Builds/Android/PressureStation.apk`를 생성합니다. Android 전환과 컴파일이 끝나면 자동으로 빌드합니다.
- Android 8.0 이상, ARM64 또는 ARMv7 기기를 대상으로 하는 테스트용 APK입니다. 앱 이름은 **Pressure Station**, 앱 식별자는 `com.pressurelab.pressurestation`입니다.
- APK 파일을 USB 등으로 스마트폰에 복사한 뒤, 휴대폰의 파일 앱에서 열어 설치하세요. 설치 권한 안내가 나오면 해당 파일 앱의 설치 허용 안내를 따라 진행하세요.
- 세로 화면에서 **영업 시작** 후 하단 주유 버튼을 길게 누릅니다. 손을 떼도 잔류 압력으로 연료가 계속 들어가는지, 앱을 다른 화면으로 전환하면 일시정지되는지 확인하세요.
- 기본 테스트 서명을 사용하는 개발용 빌드입니다. 실제 스마트폰의 터치·화면·성능 검증은 기기에서 진행해야 합니다.

## 구현 범위

- 180초 영업, 차량 3종의 가중 랜덤 등장, 일반 판정 표시 0.4초 / 초과 실패 표시 1.2초와 차량 전환 0.5초.
- 차량마다 도착 시 기존 연료를 범위 내 정수로 균등 추첨합니다. 같은 값이 다시 나올 수 있습니다. 목표량 = 탱크 용량 − 기존 연료이며 이번 방문의 주유량은 0 L부터 시작합니다.
- 경차: 탱크 40 L, 기존 연료 5–25 L, 목표 15–35 L, 저항 20, 등장 가중치 40.
- 승용차: 탱크 60 L, 기존 연료 5–45 L, 목표 15–55 L, 저항 35, 등장 가중치 40.
- SUV: 탱크 85 L, 기존 연료 5–65 L, 목표 20–80 L, 저항 48, 등장 가중치 20.
- 제한시간(초): 경차 `clamp(8 + 목표×0.17, 11, 15)`, 승용차 `clamp(10 + 목표×0.15, 12, 19)`, SUV `clamp(11 + 목표×0.13, 13, 22)`. 소수점 한 자리로 반올림하며 도착 때 정한 목표·허용범위·제한시간은 주유 도중 고정합니다.
- 압력 0–100, 기본 상승 60/s, 감압 28/s. 유량 `max(0, 압력 - 저항) × 0.20`.
- 손을 뗀 뒤 압력이 차량 저항 이하가 되어 허용범위 안이고 만료·과다 플래그가 없으면 성공. 허용 오차는 `min(5 L, 목표×20%)`: 목표 15 L은 12–18 L, 목표 20 L은 16–24 L, 목표 25 L 이상은 기존 ±5 L입니다. ±1 L 이내면 퍼펙트. 허용 상한 초과 시 입력·공급·결과를 즉시 확정합니다. 상한과 정확히 같은 양은 허용하고 이를 넘으면 실패합니다. 누르는 동안 저항 이하라는 이유로 미완료 고객을 종료하지 않습니다.
- 성공 점수 = `(100 + 정확도 보너스 + 속도 보너스) × 목표/35`, 최종 정수 반올림. 정확도는 `100×max(0, 1−절대오차/허용오차)`, 속도는 `50×clamp(남은 차량시간/제한시간, 0, 1)`입니다. 과다 주유 −80점, 시간 초과 −40점. 성공할 때 버튼을 한 번만 눌렀으면 기본 성공 점수의 10%, 최종 오차가 ±1 L 이내면 15%를 추가합니다. 두 조건은 각각 기본 점수에서 계산하고 정수 반올림해 합산합니다. 미달 후 재주유는 퍼펙트 보너스만 가능하며 실패에는 보너스를 지급하지 않습니다. 마감 후 마지막 고객도 성공하면 점수와 원터치·퍼펙트 보너스를 정상 지급합니다.
- 처리 수, 성공·실패 수, 퍼펙트·원터치 성공 수, 누적 보너스, 최대 연속 성공, 모든 판정 차량의 평균 절대 오차와 평균 처리시간.
- 한글 UI, 코드로 그린 차량·주유기·호스, 원형 압력계, 허용 범위 표시, 차량 제한시간 바, 임시 합성 사운드.
- 안전 영역과 화면 비율을 고려한 세로 레이아웃. 터치·마우스·스페이스 키 입력.
- 기본 / 빠른 감압(40/s) / 느린 감압(18/s), 상승 속도·주유 계수 변경, 차량 강제 교체, 고정 시드(기본 12345), 기존 연료 ±5 L 조정, 다시 시작. 기존 연료를 조정하면 현재 차량을 초기화합니다.
- 기본 설정의 최고 점수 저장 및 차량별 CSV 기록 저장. 마감 후 마지막 고객도 정상 정산하므로 v0.2.5 최고 기록을 이전 규칙과 분리합니다.
- 결과 화면은 목표 35 L 이하(소량)와 초과(대량)의 평균 처리시간 및 대수를 비교합니다. CSV에는 탱크·기존 연료·목표·최종 주유량·총 연료·허용 오차·제한 시간·처리 시간·주유량 구분·시드를 기록합니다.

## 합리적으로 정리한 부분

1. **엔진 버전**: 기존 프로젝트의 Unity 6.6을 유지했습니다. 2022.3으로 프로젝트를 내리지 않았습니다.
2. **시간과 판정**: 출고 연료를 먼저 반영하고 같은 시각의 고객·영업 만료를 기록합니다. 과다 주유는 발생 즉시 우선 종료하고, 그 외에는 유량 중단 시 시간 초과 → 성공 순으로 결과를 선택합니다. 부족하면 계속 주유할 수 있습니다. 영업 마감은 현재 고객의 판정·입력을 강제로 바꾸지 않고 새 고객 도착만 중단합니다. 시간 초과나 마감 중 초과가 발생해도 감점은 −80점 한 번이며, 복합 원인은 각각 기록합니다. 고객 시간은 일반·강제 감압 중과 마감 이후에도 진행합니다. 기존 시간 초과 플래그는 유지합니다. 마지막 고객은 실제 결과대로 점수·보너스·감점을 정산하며, 종료 원인과 별도로 마감 후 처리 여부를 기록합니다.
3. **연료 계산**: 단순 프레임별 Euler 누적 대신 압력 증가·감소를 구간별로 적분합니다. 차량 저항과 최대 압력 경계도 나누어 계산해 프레임 속도에 따른 연료 오차를 줄였습니다. 판정은 최대 1/240초 간격으로 진행합니다.
4. **입력 안전**: 차량 교체, 버튼 밖으로 포인터 이동, 창 포커스 상실, 일시정지 시 눌림 상태를 해제합니다. 다음 차량에는 새 입력이 필요합니다.
5. **통계 정의**: 완료 = 유량 중단 또는 초과 즉시 차단으로 최종 기록된 차량. 마지막 영업 마감 차량도 포함하며 강제 교체된 차량은 제외합니다. 처리시간은 정상·시간 초과의 경우 마지막 감압과 미달 후 재주유를 포함한 실제 시간이며, 초과 주유는 상한을 넘은 순간까지의 시간입니다. 마감 고객도 실제 처리시간을 기록하며, 전역 마감 추가시간에는 마지막 결과 표시 시간도 포함합니다. CSV는 거래ID, 시간초과·과다·영업종료 원인과 영업 마감 추가시간을 기록합니다. `flow_stopped_wait_seconds` 필드는 호환성을 위해 유지하지만 성공·강제 종료 고객은 유량 0 이후 추가 대기가 없습니다. 미달 상태로 재입력을 기다린 시간은 별도로 쌓일 수 있습니다. 같은 거래ID는 한 번만 집계합니다.
6. **기록 비교**: 플레이 도중 설정을 바꾸거나 차량을 강제 교체한 영업은 연습 영업입니다. 최고 기록은 기본 감압 및 기본 상승·유량 설정에서만 갱신합니다. CSV에는 각 차량 판정 당시의 설정을 기록합니다.
7. **테스트 도구**: 디버그 패널은 빌드에서도 직접 열 수 있게 두었습니다. 일반 게임 화면에서는 예상 최종량을 숨깁니다.
8. **소량 주유 밸런스**: 15 L 목표에 ±5 L를 적용하면 오차를 33%까지 허용하므로 소량은 20%로 줄였습니다. 점수를 목표량에 비례시켜 작은 목표가 많이 나오는 영업의 이득을 줄이고, 속도 보너스는 시간 비율로 계산해 큰 탱크의 긴 제한시간이 보너스에 그대로 더해지는 문제를 줄였습니다.
9. **탱크 초과량**: 양식대로 실제 탱크 용량을 넘어도 허용 오차 안이면 성공으로 처리합니다. 총 연료는 기존 연료 + 이번 주유량이며 진행 막대와 판정은 이번 주유량을 기준으로 합니다.
10. **도착·결과 로그**: Game Session Manager의 `Log Vehicle Data`를 켜면 시드와 도착 수치, 결과를 Console에 기록합니다. 일반 플레이에서는 기본적으로 끕니다. 고정 시드 또는 강제 연료를 사용한 영업은 연습 기록입니다.

## 설정과 파일

- `Assets/GasStation/Resources/PrototypeSettings.asset`: 차량 수치와 영업·전환·초과 실패 표시 시간, 압력·연료·허용 오차를 Inspector에서 편집.
- `Assets/GasStation/Runtime/`: 시뮬레이션, 압력 적분, 판정, 가중 스폰, 통계, 입력, UI.
- `Assets/GasStation/Tests/Editor/`: 경계 판정, 프레임 독립성, 잔류량 예측, 부족 후 재개, 시간 초과, 영업 종료, 일시정지, 3종 차량 ×3 감압 속도, 전체 영업 테스트.
- Unity 메뉴 `Gas Station > Run Gameplay Tests`: 테스트 실행, 결과는 `Verification/gameplay-tests.xml`.
- Unity 메뉴 `Gas Station > Run Input Tests`: Play 모드에서 실제 UI 버튼의 누름·해제·포인터 이탈·일시정지를 검사, 결과는 `Verification/input-tests.xml`.
- Unity 메뉴 `Gas Station > Build Windows Prototype`: Windows 개발용 빌드 생성.
- Unity 메뉴 `Gas Station > Capture Game View`: Play 중 게임 화면을 `Verification/`에 저장.
- Unity 메뉴 `Gas Station > Prepare Prototype Scene`: 기본 씬 재생성. 이미 편집한 프로토타입 씬이 있다면 먼저 별도로 보관하세요.

CSV는 결과 화면의 **차량별 기록 CSV 저장**을 누르면 Unity의 사용자 데이터 폴더(`Application.persistentDataPath`)에 저장됩니다. Windows 기본 경로는 `%USERPROFILE%/AppData/LocalLow/Pressure Lab/Pressure Station/`입니다. 정확한 저장 경로는 Unity Console에 출력됩니다.
